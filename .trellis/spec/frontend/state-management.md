# State Management

> Chat and task UI state in Dougie.

## Overview

Single source of truth is `TaskManager.task` plus `TaskManager.transcript`. `ChatViewModel` `combine`s them into `ChatUiState` (`mergeChatUiState`). Past turns are `toPastChatItems()` (user + final/error only). The live task still maps with `toChatUiState()`. Do not keep a second `TaskStatus`. Current conversation id is `PreferenceStore.currentConversationId()` (independent of `save()`). Custom window titles are a separate prefs key `conversation_titles_json` (`id` → name, `PreferenceStore.conversationTitles` / `setConversationTitle`); **保存配置** must not write or clear it. Titles are not on `AgentTask`, not in `snapshot_json`, and not sent to the LLM. Do not log the custom name.

Provider settings are a separate store: `PreferenceStore.settings: StateFlow<ProviderSettings>`. Settings form is local until **保存配置**; the next `submit` reads current `allowCloud` / key / `maxTokens` via lambdas on `EgressGateway` and `OpenAICompatibleProvider`. Choosing a vendor preset fills `baseUrl` / `model` / `maxTokens` and keeps the API key; OpenCode Go is an optional preset (`opencode-go`) and does not change the OpenAI install default; DeepSeek’s preset model is `deepseek-v4-flash`. Editing the URL off a preset switches `vendorId` to `custom`. `memoryEnabled` (default `true`) is toggled on the Memory screen via `PreferenceStore.setMemoryEnabled`; Settings **保存配置** must copy the current flag so it is not reset. `modelTreeUri` is persisted immediately via `PreferenceStore.setModelTreeUri` when the user picks a folder; **保存配置** must copy the current URI so it is not reset. Open-app allowlist JSON is a **separate** prefs key (`setOpenAppsJson`); **保存配置** must not write or clear it. `ttsSpeakerId` is persisted immediately via `PreferenceStore.setTtsSpeakerId` (curated sids only); **保存配置** must copy it so the LLM save does not reset the voice. Settings must not auto-scan the external tree on open; **刷新** (or picking a folder) copies/hashes. Until then, “已安装” falls back to `filesDir`. Offline model **测试** is one-shot per row until the next install: disable while any row is probing, and after `probeOk == true`. While a row is probing, show **取消** (same as download). Time out ASR/TTS at 90s and intent / chat at 180s so 测试中 cannot stick forever; cancel must clear `probing`. Run the probe on `Dispatchers.Default`.

## Pattern

```kotlin
val uiState: StateFlow<ChatUiState> = combine(taskManager.task, taskManager.transcript) { live, past ->
    mergeChatUiState(live, past)
}.stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), ChatUiState())
```

`ChatItem`: `UserMessage` | `Thinking(loopNumber, live)` | `ToolCard` | `ConfirmCard` | `AgentMessage(text, memorySources, durationLabel)`. Each item has a unique `listKey` (`{taskId}:user` / `{taskId}:agent` / `{taskId}:thinking-n` / tool or confirm id). Chat `LazyColumn` must use `item.listKey` — type-only keys like `"user"` crash as soon as two turns share the window. Keep Thinking then ToolCard as two feed rows; do not merge them. Bubble enter is `nextChatItemEnter(items, seenKeys)` (`ChatItemEnter(playKeys, seenKeys)`): `seenKeys == null` (first `ChatScreen` composition after `ChatRoute` mounts) → `playKeys` empty, seed every current key including Confirm; empty `items` → both sets empty so the next send can play; otherwise `playKeys` are unseen keys that are not `ConfirmCard`, and next `seenKeys` is the union with every current key. Same `{taskId}:agent` streaming → final (including `durationLabel`) does not replay. `ChatScreen` keeps `seenKeys` so `EmptyState` still seeds an empty set; do not key this off `firstKey`. `UserMessage` / `Thinking` / `AgentMessage` in `playKeys` use 200ms FastOutSlowIn bubble enter (fade + 8dp). `ToolCard` stays in `playKeys` but `ChatFeed` uses `ToolSwitchEnterMotion` (150ms LinearOutSlowIn fade, no `translationY`). Same-key Thinking live→「循环 n」 and ToolCard title 准备/正在调用 → 已调用/失败 use `AnimatedContent` 150ms LinearOutSlowIn; first composition shows the current state. Enter uses `graphicsLayer` (not layout), so it must not change `shouldFollowChatFeed` / `pendingFocusKey` / `listKey`. Confirm overlay is `nextConfirmEnter(confirmKey, initialized, lastKey)` (`ConfirmEnter(play, initialized, lastKey)`): first composition (`initialized == false`) seeds `lastKey` with `play = false`; after that a new non-null key that is not `lastKey` plays; the same key does not replay; `lastKey` follows the current key including null. `chatConfirmCard` takes the last Confirm; `ChatFeed` receives `chatFeedItemsWithoutConfirm` so the list does not draw a second card. ChatRoute follow/`scrollToItem` / `rememberFeedFollow` use that same feed list so `lastIndex` is not the Confirm row. Overlay covers only the feed `Box(weight(1f))`. Confirm overlay still is not a feed row; after confirm, the new `tool-{id}` uses switch fade, not bubble enter.

`Thinking.live` is true only for the current `PREPARING`/`THINKING` chip. Chips before already-run tools are not live: copy `循环 n`, no pulse, never “KISS” or lingering “思考中”. Live copy is `思考中… [循环 n]`. Chat `LazyColumn` scroll lives on the Activity-scoped `ChatViewModel` (`shouldFollowChatFeed`); leaving Chat for 记忆/任务/设置 must not re-animate to the end of a long thread. A History card tap sets `ChatViewModel.requestFocus(taskId)` (`{taskId}:user`); while that `pendingFocusKey` is set, `shouldFollowChatFeed` must not pin to the last item — `ChatRoute` `scrollToItem`s the user bubble (wait until the key exists; if the loaded window never has it, fall back to follow-to-end). After that scroll, `rememberFeedFollow` then clear pending so the follow effect does not pin to end. `send` / `retry` / `newConversation` clear pending. Bottom-nav **对话** does not `requestFocus`.

When `status == COMPLETED`, the Final `AgentMessage` copies citation labels from `citationSources()`: memory `source` first, then conversation hit `sourceLabel`, trim, skip blanks, keep order, drop exact duplicates. Never put fact `content` or hit `user`/`assistant` on the bubble, and never use a conversation UUID as the label (blank `source` / `sourceLabel` is omitted). Streaming and `FAILED` `AgentMessage`s stay source-less. Empty memories and hits (or all-blank labels) → no citation UI. Chat maps from `AgentTask` values (`task` + `transcript`); do not open SQLite in `:feature:chat`. `priorTurns` stay current-window only; LLM turns search all windows via `retrievedConversationHits`. Past transcript turns omit tool cards. `canNewConversation` is true when the window is not empty and the live task is idle. Top bar **新对话** confirms then `TaskManager.newConversation()`. Chat top bar keeps 24sp **Dougie**; the next line is the current window display name (`conversationTitle`, 12sp `OnSurfaceVariant`, single-line ellipsis, not clickable) — History **改名** only, not Chat. Empty unlisted windows (current id not in `listRecent(50)`, transcript+task empty, not default) show 「新对话」; default empty stays 「默认会话」 unless custom. After the first turn, Chat uses the same numbered fallback as History.

Debug maps `TaskManager.task` to `DebugTaskSnapshot` (`taskId`, `status`, `loopCount`, `lastError`, `completionPath` as `completionPath?.toUserLabel() ?: "无"` → 本地意图 / 本地 LLM / 远程 LLM / 无) plus `AuditLog.listRecent` rows — never a second `TaskStatus` store, never `resultJson` / prompt / tool args. LoopEngine writes `LOCAL_LLM` when `provider.isLocal` on the LLM loop, `REMOTE_LLM` for cloud. MiniRBT `LOCAL_INTENT` runs only when `skipIntentShortcut` is false (no conversational LLM: cloud unconfigured and local chat pack not ready). Speak / match-then-tap / exact `打开`+allowlist-alias phrases still set `LOCAL_INTENT` even when MiniRBT is skipped. Cloud-on chat is not MiniRBT-first.

`inputEnabled` is false while the task is busy (not COMPLETED/FAILED/IDLE), including `AWAITING_CONFIRMATION`. `canCancel` is that same busy bit (`!inputEnabled`). The composer right slot is **终止** (`Icons.Filled.Stop`, `ChatViewModel.cancel()` → `TaskManager.cancel()`) while `canCancel`; text, attachments, and mic stay gated by `inputEnabled` — do not set `inputEnabled` true to light the button. Completed TTS **停止播报** is only when not busy; if busy and `speakingReply` overlap, **终止** wins and also stops speech. `canRetry` is true only when `status == FAILED`. `canSpeakReply` is true only when `status == COMPLETED` so the last bubble **播报** is hidden while streaming and on FAILED (FAILED still uses **重试**). Chat **重试** calls `TaskManager.submit` with the same `input` (new `taskId`) and copies `speakReply` and `conversationId`. Bottom nav **任务** opens `:feature:history`. Empty search box groups `TaskStore.listRecent(50)` via `toHistorySections` (section order = first appearance of each `conversationId`, most recently active on top; cards inside a section stay newest-first; sticky titles; `"default"` → 「默认会话」, other windows 「对话 2」… by oldest-first first appearance among those 50, skipping default, never UUID). Non-empty query uses `conversationSearchNeedles` + `searchHistory` (full-table, `COMPLETED`/`FAILED`, haystack `input`+`finalAnswer`+`lastError`) UNION title hits: prefs custom names match even if that window is outside the current 50; numbered 「对话 n」 names use the recent-50 grouping. If the window display name matches, include all terminal tasks of that `conversationId` (`listByConversation`, not `listRecent(50)`). Empty needles (e.g. only 「这个」) → empty list, not the recent 50. No-match copy 「没有匹配的任务」; blank query and empty store 「还没有任务记录」. Search lives on `HistoryViewModel` (`query` in `HistoryUiState`), not Activity. Cards map `AgentTask.toHistoryItem`: `durationLabel` from `formatTaskDuration(startedAt, endedAt)` (missing either timestamp → null, never `updated_at`); `providerLabel` from `completionPath?.toUserLabel()` (null omits, never 「无」); `completedAtLabel` from `formatCompletedAt(endedAt)` (null `endedAt` omits; device-local 今天/昨天/`M月d日`/`yyyy年M月d日` + `HH:mm`, minute precision, never seconds, never relative time, never `updated_at`); `steps` from `toolTrace` (`HistoryToolStep`: raw `toolName`, SUCCESS→成功 / FAILED→失败 / else 进行中; empty trace → empty list; never `argsSummary` / `resultJson`). `HistoryCard` draws one 13sp `OnSurfaceVariant` meta line `listOfNotNull(duration, provider, completedAt).joinToString(" · ")` and skips the Text when all three are empty. Loop row keeps `循环 n · toolChain` and, when `steps` is not empty, a **展开** / **收起** `TextButton` (`remember(taskId)`, not persisted; expanded lines 13sp `OnSurfaceVariant` Monospace `$toolName  ·  $statusLabel`). Nested **展开** must not `openConversation`. Every card also has **删除** (`DougieColors.Error`) next to **展开**; it must not `openConversation`. Confirm 标题「删除任务」, 正文「将删除这一轮，且无法恢复。」 Confirm calls `TaskManager.deleteTask(taskId)` (busy → no-op, including other windows). After delete, History `refresh()` plus Activity `listRecent(50)` snapshot (same as window delete). If that non-default window now has 0 tasks, clear its title and `openConversation(default)` when it was current; default emptied stays empty default. In-progress may show Provider without duration or completed-at. Chat COMPLETED/FAILED `AgentMessage` copies `durationLabel` from the same `:core:model` `formatTaskDuration` (both timestamps required; streaming/thinking/missing timestamps stay null; caption is not bubble `text`). Chat does not show Provider or completed-at. A custom title from prefs overrides that fallback (`conversationDisplayName`); blank/whitespace clears it. Sticky header has **改名** (dialog, prefill current display name, 保存/取消) which calls `ConversationTitles.setTitle` and does not `openConversation` or switch windows — busy does not block rename. Non-default sections also have **删除** (`DougieColors.Error`, `contentDescription` 删除) next to 改名; default has no delete. **删除** opens a confirm dialog (标题「删除会话」, 正文「将删除「{显示名}」中的全部任务，且无法恢复。」, 删除/取消) and must not `openConversation`. Confirm calls `TaskManager.deleteConversation(id)` then History `refresh()`. `:app` must also refresh the Activity `listRecent(50)` snapshot used by `currentConversationTitle` — History `refresh()` alone leaves Chat 「对话 n」 numbering stale when a sibling extra window is removed (especially when that extra had no custom title, so `conversationTitles` does not emit). `deleteConversation` no-ops when `isBusy()` or id is blank/`default` (does not delete rows or titles). Deleting the current window sets the pointer to `default` and loads that transcript (`openConversation` semantics). Custom title is `setTitle(id, "")`. Do not log the name. Tapping a card body (summary, status, duration, Provider, completed-at, loop text, error) calls `TaskManager.openConversation(conversationId)` plus `ChatViewModel.requestFocus(taskId)` and returns to Chat (no-op while busy). Focus is scroll-only: `openConversation` still seeds the latest turn for 播报/重试. `openConversation` is async: after load, apply rows only if `conversation.currentId()` is still that id and the manager is not busy — otherwise a slow load can undo **新对话**. `mergeChatUiState` must drop past rows whose `taskId` equals the live task. Cold start with only completed turns leaves `task` null, so **播报** / **重试** stay off until the user sends or opens the thread from **任务**. `:feature:memory` must `refresh()` whenever `MemoryRoute` is shown (`LaunchedEffect`), not only in `ViewModel.init` — the Activity-scoped ViewModel otherwise keeps an empty list after Chat ingests a fact.

`speakingReply` is Activity UI state in `:app` (`MainActivity`), not a second `TaskStatus` and not a field on `ChatUiState`. Map loop status from `AgentTask` only. Busy **终止** is `canCancel` from the mapper. The TTS **停止播报** button and **正在播报...** line are driven by the host `speakingReply` flag when the task is not busy.

When `status == AWAITING_CONFIRMATION`, map the last `ToolTraceEntry` to `ConfirmCard(toolName, argsJson, riskLevel, toolCallId)` instead of a `ToolCard`. Chat draws that card in `ConfirmCardOverlay` over the dimmed feed, not as a `LazyColumn` row. Scrim clicks consume and do nothing (not reject, not cancel). `ChatViewModel.confirm()` / `reject()` call `TaskManager` and must not store a second confirmation flag. Composer **终止** still cancels the round.

If `streamingText` is not blank and status is not COMPLETED/FAILED, append `AgentMessage(streamingText)` even while `THINKING` (no citations). After complete, show `finalAnswer` only (`streamingText` is null), with `memorySources` when memories were retrieved. `COMPLETED` with blank `finalAnswer` adds no Agent bubble — LoopEngine must fail `LLM_EMPTY_REPLY` instead.

Tool cards: `battery` → 电池工具, `time` → 时间工具, `screen_capture` → 截取屏幕, `speech_output` → 念出来, `calendar_query` / `calendar_create` / `clipboard_*` use Chinese labels, else the raw `toolName`. Do not hardcode “电池” for every tool. `ToolTraceStatus.showsToolProgress()` is true only for `PENDING` / `EXECUTING`; `ToolCallCard` draws the indeterminate bar from that. `SUCCESS` / `FAILED` completed cards have no bar. Confirm overlay is not a `ToolCard` and has no bar. High Risk step name stays the title `toolDisplayName`. Intent shortcut `screen_capture` success pins that frame into the Chat composer (JPEG preview, same as overlay `addScreen`) after the task finishes; `TaskManager.clearPin()` still runs, but `:app` must not `releaseAfterTask`/`clearAll` for that `LOCAL_INTENT` success. LLM-loop `screen_capture` (`REMOTE_LLM` / `LOCAL_LLM`) does not add a chip and still `releaseAfterTask`. Sideload may show a separate overlay-capture hint under Chat; it is not `finalAnswer` and is not a `ChatItem`.

Egress / timeout / network / cancel failures are not a separate UI type: they are `AgentMessage` text from `lastError`.

## Don't: Duplicate loop status in ViewModel

Do not keep a second `mutableStateOf` copy of `TaskStatus`. Map from `AgentTask` only so Fake tests and the real provider stay consistent.
